### Key Design Decisions

**1. Modular Architecture**
Each system independently testable:
- Puzzles: Generate and validate solutions
- Nodes: Manage state and security
- Tools: Track uses and effects
- Detection: Calculate threat levels
- Levels: Generate networks
- Game: Orchestrate systems

Benefits: Easy testing, extension, maintenance; clean separation of concerns

**2. Puzzle Variety via Type Mapping**
- Gateway → Port scanning (identify vulnerabilities)
- Server → Password cracking (common passwords)
- Database → Encryption breaking (Caesar cipher)
- SecurityHub → Privilege escalation (permission chains)
- DataCache → Firewall navigation (protocol rules)

Result: Each node type requires different tactical approach

**3. Progressive Difficulty Curve**
- Early levels (1-3): High time, low security, large time windows
- Mid levels (4-7): Balanced challenge, moderate difficulty
- Late levels (8-10): Tight time limits, high security nodes
- Expert levels (11-12): 60s limit, maximum security

Result: Smooth progression from learning to mastery

**4. Risk vs. Reward Mechanics**
- Successful hack: +3× security = More detection but more points
- Failed attempt: +2× security = Less detection but no points
- Network Mask: 50% detection reduction at cost of tool use

Result: Strategic decisions about which nodes to target

**5. Single-Entry Point (Gateway)**
- Gateway starts pre-hacked
- Lowest security node
- Must hack to access network
- Ensures fair starting position for all players

Result: Clear learning path and game progression

### Implementation Challenges & Solutions

**Challenge 1: Variable Test Complexity**
Initial issue: Some tests had incorrect assumptions about game behavior
- Gateway nodes start hacked, so re-hacking returns "already hacked" (no score)
- Detection doesn't increase on insufficient tools failures

Solution: Adjusted tests to match actual intended behavior
- Tests now validate correct scenarios
- All edge cases properly handled
Result: 64/64 tests passing

**Challenge 2: Puzzle Difficulty Calibration**
Needed puzzles to be solvable yet challenging
- Puzzle attempts scale inversely with difficulty
- Easy puzzles (difficulty 1): 9 attempts
- Hard puzzles (difficulty 10): 0 attempts max before lock

Solution: Formula: maxAttempts = Math.max(minimum, 10 - difficulty)
Result: Difficulty properly scales puzzle challenge

**Challenge 3: Level Generation Consistency**
Random levels needed to be valid and progressively harder
- Must ensure all connections reference existing nodes
- Security must scale without exceeding 1-10 range
- Node count must increase gradually

Solution: Deterministic generation with level-based seeding
Result: Each level generates unique but valid networks

**Challenge 4: Detection System Balance**
Detection needed to be threatening but fair
- Too high increase = game unwinnable
- Too low increase = no tension
- Network Mask needed to feel useful but not overpowered

Solution: Detection = (security × multiplier) / toolEffect
- Base multiplier: 3 (success) or 2 (failure)
- Network Mask: 2× effect = 50% reduction
Result: Balanced risk-reward with strategic tool usage
