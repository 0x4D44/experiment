# Time Loop Detective - Development Journal

## Game Concept
A mystery-solving detective game with time loop mechanics. The detective is trapped in a repeating time loop and must gather clues that persist across loops. NPCs follow daily routines that can be learned and exploited. Multiple solutions to break the loop exist, and dialogue trees change based on accumulated knowledge.

## Design Decisions

### Technology Stack
- **Language**: TypeScript
- **Runtime**: Web-based (HTML5 Canvas / DOM)
- **Testing**: Jest unit tests
- **Reasoning**: Previous successful game implementations in this competition used TypeScript + web-based approach. Fast iteration, easy testing, immediate visual feedback.

### Core Game Architecture

#### State Management
- Global game state with time tracking (15-minute increments)
- Evidence inventory system
- NPC routine data structure
- Dialogue tree state tracker
- Loop counter and break conditions

#### Game Flow
1. Detective wakes up at 6:00 AM in time loop
2. Time advances in 15-minute intervals
3. NPCs follow schedules (5 characters minimum)
4. Player gathers evidence and talks to NPCs
5. Evidence persists across loop resets
6. Multiple paths to break the loop based on evidence

#### Key Features
- Time-based UI showing current time
- Evidence inventory with descriptions
- NPC interaction system with dialogue trees
- NPC schedule visualization
- Multiple endings based on collected evidence
- Save/load loop progress

## Technical Notes

### NPC Routine Structure
```
NPC {
  name: string
  schedule: {
    timeSlot: string (15-min intervals)
    location: string
    activity: string
    dialogue: DialogueTree
  }[]
}
```

### Evidence Structure
```
Evidence {
  id: string
  name: string
  description: string
  location: string
  requiredTime: string
  prerequisites: string[]
  pointsToLoop: string[]
}
```

### Loop Breaking Conditions
Multiple paths implemented:
1. Gather all evidence and confront culprit directly
2. Use evidence to convince key NPC to help
3. Blackmail approach (if evidence permits)
4. Time manipulation if specific items gathered

## Known Challenges & Solutions
- Balancing complexity with playability
- Ensuring reasonable discovery path without being too easy
- Managing dialogue state transitions
