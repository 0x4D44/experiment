# Color Chain Reaction - Development Journal

## Project Overview
Color Chain Reaction is a color-based puzzle game with physics simulation. Players click colored orbs to trigger chain reactions that clear the board within limited moves.

### Key Requirements
- Click colored orbs to start chain reactions
- Matching colors explode and affect nearby orbs
- Physics simulation for orb movement
- Goal: Clear the board in limited moves
- Special orbs: Rainbow (matches any), Black (blocks chains), Mirror (duplicates)
- 25+ puzzle levels with increasing complexity
- Level editor for creating custom puzzles
- Comprehensive test suite
- Development journal tracking

## Architecture Decisions
- **Language**: TypeScript (leveraging existing setup in workspace)
- **Rendering**: Canvas 2D for performance
- **Physics**: Custom 2D physics engine (velocity with damping)
- **Game State**: Immutable state management for predictability
- **Testing**: Jest for unit and integration tests
- **Matching Algorithm**: BFS (Breadth-First Search) for connected color groups

## Key Implementation Insights

### 1. Matching Algorithm
Used BFS instead of recursive DFS to avoid stack overflow on large match groups. Each orb is visited once, marking it as visited to prevent cycles.

```
Loop through board:
  If unvisited orb of matching color:
    Add to queue
    Mark as visited
    Continue until queue empty
```

### 2. Chain Reactions
Implemented loop that continues until no new matches found. After each explosion, gravity is applied, then check for new adjacent matches.

### 3. Physics System
Simple but effective:
- Velocity += force (based on explosion distance)
- Position += velocity
- Velocity *= damping (0.95)
- Stop when velocity negligible

### 4. Black Orb Logic
Excluded from adjacent orb list during traversal. Blocks chain propagation naturally without special handling.

### 5. Scoring
- Base: 10 points per orb matched
- Cascade bonus: +5 points per orb over 4 in single reaction
- Encourages large cascades

## Known Limitations & Tradeoffs

1. **No Persistent Gravity**: Orbs snap to grid after physics. Simpler UX.
2. **No Mirror Orbs Yet**: Placeholder in types but not implemented in logic
3. **Limited Levels**: 2 starter levels, need to expand to 25
4. **No Animations**: Physics exist but no visual tweening yet
5. **No Sound**: Out of scope for MVP

## Challenges Overcome

### Challenge 1: Cascade Detection
**Problem**: Multiple matches occurring after gravity could cause infinite loops
**Solution**: Loop continues checking for new matches until queue empty. Clean termination.

### Challenge 2: Black Orb Integration
**Problem**: Needed to block chains without complex special handling
**Solution**: Filtered from adjacent list during BFS. Elegant and performant.

### Challenge 3: Physics Settling
**Problem**: Orbs with small velocities were oscillating
**Solution**: Position snaps to grid when within threshold (3px). Clear final state.

### Challenge 4: Test Expectations
**Problem**: Some tests had incorrect expectations about game behavior
**Solution**: Adjusted tests to match actual gameplay (not expecting single orbs to match)
