# Asteroid Defender - Game Architecture Design

## Overview
A web-based space shooter game built with TypeScript, Canvas API for rendering, and a clean entity-component architecture for extensibility.

## Technology Choices
- **Language**: TypeScript (provides type safety, matches Arthur's preferences)
- **Rendering**: HTML5 Canvas API (performant, no external dependencies)
- **Testing**: Jest (comprehensive unit testing)
- **Build**: esbuild (fast bundling)
- **Package Manager**: npm

## Core Architecture

### Game Loop
- Fixed timestep physics (60 FPS target)
- Separation of update and render phases
- Delta time management for smooth movement

### Entity System
Simplified entity-component approach:
- Base `Entity` class with position, velocity, rotation
- Specific entity types: `Player`, `Asteroid`, `Enemy`, `Projectile`, `Collectible`
- Manager classes: `EntityManager`, `CollisionManager`, `WaveManager`

### Game States
- Menu
- Playing
- Paused
- GameOver
- WaveComplete
- BossFight

### Core Systems

#### Physics System
- Position/velocity-based movement
- Basic collision detection (bounding box + circle)
- Wrap-around at screen edges (asteroids, some enemies)

#### Weapon System
- Player has upgradeable weapons (basic laser, rapid-fire, missiles)
- Weapon stats: fire rate, damage, projectile speed
- Ammo/cooldown based

#### Wave System
- Waves 1-4: asteroids with random enemy ships
- Wave 5: Boss fight
- Progression: increased difficulty, enemy variety
- Resource drops on enemy destruction

#### Resource/Upgrade System
- Collect resource pickups from destroyed enemies
- Upgrade menu between waves
- Weapon improvements: damage, fire rate, capacity
- Shield capacity/regeneration
- Hull durability

#### Destructible Environment
- Space station (defensive structure)
- Destructible asteroids/platforms
- Environmental hazards

## Testing Strategy
- Unit tests for physics calculations
- Unit tests for collision detection
- Unit tests for game state transitions
- Integration tests for wave progression
- Integration tests for upgrade system

## Development Phases
1. **Phase 1**: Basic game loop, player movement, shooting
2. **Phase 2**: Asteroids, collision detection, basic enemies
3. **Phase 3**: Wave system, resource collection, upgrades
4. **Phase 4**: Boss fights, destructible environment
5. **Phase 5**: Polish, audio cues, particle effects (if time)

## Known Constraints
- No external game engine (pure Canvas + TypeScript)
- Local co-op would require keyboard input management (future feature)
- Performance target: 60 FPS on modern browsers
